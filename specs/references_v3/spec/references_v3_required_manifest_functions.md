# Manifest Keys Reference

**Terminology
- Global ledger: a top-level running track of a type of action within a manifest file
- Home dir: the top directory that is dedicated to one specific information set
- Manifest: a data structure that is currently automatically created as/in a JSON file
**

Manifest files, `manifest.json`, hold metadata relating to CsvPath Framework
assets and the actions that happen to them. Manifests are either:
- Global ledgers tracking registrations, loads, and runs
- Descriptions of individual files, csvpath statements, or runs

There are seven manifest schemas.
| Type | Location | Description |
|---|---|---|
| Registrations ledger | Named-files root | One entry per file registration |
| Named-file | The named-file's home dir | One entry per registered file |
| Named-paths groups ledger | Named-paths root | One entry per load of a named-paths group |
| Named-paths group | The named-paths group home dir | One entry per load of the group |
| Named-results ledger | Archive root | One entry per individual csvpath run |
| Named-results | The named-results run home dir | One file with one entry |
| Named-results csvpath | A csvpath's home dir within the run dir | One file with one entry |

Each table below lists every key that schema actually writes, in write order.
The Optional column marks a key that is only written under some condition,
not on every entry, and is blank otherwise. The `References v3 Function` column
names whatever v3 function gives the most specific access to that key's value.

Unless otherwise noted, every field in this document, meaning every field in a manifest.json file,
must be accessible by v3 reference in two ways:
- By retrieving the manifest file or a manifest file entry as a JSON object
  using the `:manifest()` function
- Using a more specific function that retrieves just that specific item of
  data, as listed below

## 1. Named-File Manifest (per named-file)

The named-file manifest is written by `csvpath/managers/files/file_registrar.py`.
It is one flat, append-only array per named-file, one entry per registered version.

| Field | Optional | References v3 Function | Description |
|---|---|---|---|
| type |  | :type() | File extension. E.g. `csv`, `xlsx`, etc. |
| reference |  | :reference() | A complete unique reference to a version of a registered file. This is as exact as providing the UUID for the purpose of obtaining the registered bytes. However, because it is the fingerprint of the bytes, and we allow the same bytes to be registered at different paths within the named file, the reference is not necessarily to the same registration event as produced the fingerprint. In practice this distinction rarely make a difference. And the benefit of using the fingerprint is that the fingerprint can be constructed using the bytes, even if it is not certain where those bytes may have been registered within the named-file. In general, be confident that you will get the correct bytes, but mindful that those bytes may be registered multiple times if, and only if, the registrations happened under different paths within the named-file. |
| file |  | :file() | The Path from root to the file containing this information. |
| file_home |  | :file_home() | The path to the directory representing the original physical file registered and named by the same name, including extension. This directory holds the version files. The path is constructed using the [inputs] files key in config.ini. That means in some contexts, for e.g. FlightPath Server, it will always be fully qualified to the filesystem root. File homes are derived using a template, if one is provided in the registration method call or a default is configured for the named-file. |
| fingerprint |  | :fingerprint() | In most cases, the SHA256 hash of the bytes. The exception is: files in S3 are identified by MD5 hash because AWS calculates that for us, improving performance at the tiny risk of a hash collision. For our purposes, the MD5 is equally effective to the SHA256. |
| uuid |  | :uuid() | A UUID identifying the registration that this manifest entry represents. The UUID is typically generated by the Framework at registration-time; however, it is possible to submit a pre-created UUID with the registration method call. FlightPath Server does the latter so that it can regester files asynchronously. |
| time |  | :time() | The moment the registration occurred in UTC. |
| from |  | :source() | The source path of the original data file that is registered and copied into the named-file. This is the path segments data that the named-file's default template, or a template provided by the user at registration-time, uses to construct the path within the named-file. |
| mark | optional | N/A | The name of a worksheet in an Excel file. This is accessible via `name_two` |
| template |  | :template() | A string with braces-bracketed replacement tokens that determines the path within the named-file of the file home, where a registered file is stored. The replacement tokens are of two kinds: 1. the indexes of the path segments found in the origin path. E.g. :0 for the first directory below the root, :1 for the next path segment, and so on, and 2. tokens for elements of the current datetime, e.g. :day, :month, :year, etc. |

## 3. Named-Paths Manifest (per named-paths group)

append-only array per named-paths group, one entry per loaded/reloaded version
of the whole group.

| Field | Optional | References v3 Function | Description |
|---|---|---|---|
| archive_name |  | :archive() | The `[results] archive` value from `config.ini` at the time the current version of the named-paths group was loaded. |
| named_paths_name |  | :named_paths_name() | The named of this named-paths group. |
| named_paths_home |  | :home() | The path to the root directory of this named-paths group. The `[inputs] csvpaths` value from `config.ini`, the path to the root of all named-paths groups, is used to construct this path. |
| group_file_path |  | :group_file() | The path to the `group.csvpaths` file that contains all the csvpath statements in the group. Every named-paths group has this file. |
| source_path | optional | :source() | The path to the file or directory that housed the csvpath statements that make up the contents of the version of this named-paths group this entry represents. |
| named_paths |  | :named_paths() | The full byte-for-byte text of the csvpath statements comprising this entry's version of this named-paths group. The value of this key can potentially be quite large. |
| named_paths_identities |  | :identities() | A list of the identities of the csvpaths in this version of this named-paths group. Identities are the names given to csvpaths in their leading comments using standard metadata keys (:id, :Id, :ID, :name, :Name, :NAME; in that order of precedence) or, if a name is not found, the 0-based index of their position within the named-paths group. |
| named_paths_count |  | :identities_count() | The number of csvpaths in this version of the named-paths group. |
| fingerprint |  | :fingerprint() | In most cases, the SHA256 hash of the `group.csvpaths` file. The exception is: files in S3 are identified by MD5 hash because AWS calculates that for us, improving performance at the tiny risk of a hash collision. For our purposes, the MD5 is equally effective to the SHA256. |
| time |  | :time() | The moment this version of the named-paths group was loaded. |
| time_started | optional | N/A | Technically, the beginning moment of the load. Use `:time()` |
| time_completed | optional | N/A | Technically the end moment the load completes. A long running load is quite unlikely. |
| uuid |  | :uuid() | The unique identifier for this version of the named-paths group. |
| manifest_path |  | :manifest() | The path to this file. |
| template | optional | :template() | The default run dir template. A string with braces-bracketed replacement tokens that determines the path within the named-results of the run directory (typically referred to as the run dir), where results are stored. The replacement tokens are of two kinds: 1. the indexes of the path segments found in the origin path. E.g. :0 for the first directory below the root, :1 for the next path segment, and so on, and 2. tokens for elements of the current datetime, e.g. :day, :month, :year, etc. |

| named_file_name |  | :named_file_name() | The name of the named-file this run took as it's data input. |
| named_file_uuid |  | :named_file_uuid() | The UUID that uniquely identifies the version of the named-file that was the data source for the run. |
| named_file_path |  | :named_file_path() | The path to the named-file version. |
| named_file_size |  | :named_file_size() | The byte size of the named-file version used, read from the filesystem at the moment the run started. | named_file_last_change |  | :named_file_last_change() | The last-modified timestamp of the named-file version used, read from the filesystem at the moment the run started. | named_file_fingerprint_on_file |  | :manifest() | Deprecated. Do not use. |
| hostname |  | :host() | If available, the name of the computer where the process that performed the run was. |
| ip_address |  | N/A | Do not use. |
| username |  | :username() | If available, the user owning the process that performed the run. |

| manifest_path |  | :manifest() | The path to this manifest. |

## 9. Named-Paths Definition (definition.json, per named-paths group)

Created by `csvpath/managers/paths/paths_descriptor.py` A single dict,
stored in the same home directory as the Named-Paths Manifest. Not
versioned.

| Field | Optional | References v3 Function | Description |
|---|---|---|---|
| template | optional | :template() | The default run-dir template for this named-paths group.
