# Manifest Keys Reference

Seven manifest schemas, confirmed directly against each registrar's/listener's
own `metadata_update()` (not assumed) as of 2026-08-06. Each table lists every
key that schema actually writes, in write order, with a blank Description
column to fill in. `(optional)` marks a key that is only written under some
condition, not on every entry.

This is a description-of-what-exists document, independent of any decision
about which keys should become references-v3 functions — that's a separate,
later exercise built on top of this catalog.

---

## 1. Named-File Manifest (per named-file)

`csvpath/managers/files/file_registrar.py` — one flat, append-only array per
named-file, one entry per registered version. This is the manifest
`FilesReferenceFinder3`/`:manifest()` actually reads today.

| Schema | Field | Description |
|---|---|---|
| Named-File Manifest | type |File extension. E.g. `csv`, `xlsx`, etc. |
| Named-File Manifest | reference |A complete unique reference to a version of a registered file. This is as exact as providing the UUID for the purpose of obtaining the registered bytes. However, because it is the fingerprint of the bytes, and we allow the same bytes to be registered at different paths within the named file, the reference is not necessarily to the same registration event as produced the fingerprint. In practice this distinction rarely make a difference. And the benefit of using the fingerprint is that the fingerprint can be constructed using the bytes, even if it is not certain where those bytes may have been registered within the named-file. In general, be confident that you will get the correct bytes, but mindful that those bytes may be registered multiple times if, and only if, the registrations happened under different paths within the named-file. |
| Named-File Manifest | file |The Path from root to the file containing this information. |
| Named-File Manifest | file_home |The path to the directory representing the original physical file registered and named by the same name, including extension. This directory holds the version files. The path is constructed using the [inputs] files key in config.ini. That means in some contexts, for e.g. FlightPath Server, it will always be fully qualified to the filesystem root. File homes are derived using a template, if one is provided in the registration method call or a default is configured for the named-file. |
| Named-File Manifest | fingerprint |In most cases, the SHA256 hash of the bytes. The exception is: files in S3 are identified by MD5 hash because AWS calculates that for us, improving performance at the tiny risk of a hash collision. For our purposes, the MD5 is equally effective to the SHA256. |
| Named-File Manifest | uuid |A UUID identifying the registration that this manifest entry represents. The UUID is typically generated by the Framework at registration-time; however, it is possible to submit a pre-created UUID with the registration method call. FlightPath Server does the latter so that it can regester files asynchronously. |
| Named-File Manifest | time |The moment the registration occurred in UTC. |
| Named-File Manifest | from |The source path of the original data file that is registered and copied into the named-file. This is the path segments data that the named-file's default template, or a template provided by the user at registration-time, uses to construct the path within the named-file. |
| Named-File Manifest | mark (optional) |The name of a worksheet in an Excel file. When there is a mark, the workbook as a whole is registered, using a fingerprint of the whole file for versioning purposes. However, the mark is captured so that when you ask for the named-file by name the Framework takes account of the mark and returns just the worksheet that is technically the data that was the target of the registration. The impact of this difference between fingerprint and worksheet content is expected to be low. It is possible that a worksheet might remain static between two attempted registrations, but data outside that specific worksheet changed, resulting in a new registration with a new fingerprint and UUID, but still asserting only the unchanged worksheet.  |
| Named-File Manifest | template |A string with braces-bracketed replacement tokens that determines the path within the named-file of the file home, where a registered file is stored. The replacement tokens are of two kinds: 1. the indexes of the path segments found in the origin path. E.g. :0 for the first directory below the root, :1 for the next path segment, and so on, and 2. tokens for elements of the current datetime, e.g. :day, :month, :year, etc. |

## 3. Named-Paths Manifest (per named-paths group)

`csvpath/managers/paths/paths_registrar.py` — one flat, append-only array per
named-paths group, one entry per loaded/reloaded version of the whole group.
This is the manifest `CsvpathsReferenceFinder3`/`:manifest()` actually reads
today.

| Schema | Field | Description |
|---|---|---|
| Named-Paths Manifest | archive_name |The `[results] archive` value from `config.ini` at the time the current version of the named-paths group was loaded. |
| Named-Paths Manifest | named_paths_name |The named of this named-paths group. |
| Named-Paths Manifest | named_paths_home |The path to the root directory of this named-paths group. The `[inputs] csvpaths` value from `config.ini`, the path to the root of all named-paths groups, is used to construct this path.  |
| Named-Paths Manifest | group_file_path |The path to the `group.csvpaths` file that contains all the csvpath statements in the group. Every named-paths group has this file. |
| Named-Paths Manifest | source_path (optional) |The path to the file or directory that housed the csvpath statements that make up the contents of the version of this named-paths group this entry represents. |
| Named-Paths Manifest | named_paths |The full byte-for-byte text of the csvpath statements comprising this entry's version of this named-paths group. The value of this key can potentially be quite large. |
| Named-Paths Manifest | named_paths_identities |A list of the identities of the csvpaths in this version of this named-paths group. Identities are the names given to csvpaths in their leading comments using standard metadata keys (:id, :Id, :ID, :name, :Name, :NAME; in that order of precedence) or, if a name is not found, the 0-based index of their position within the named-paths group.  |
| Named-Paths Manifest | named_paths_count | The number of csvpaths in this version of the named-paths group.|
| Named-Paths Manifest | fingerprint |In most cases, the SHA256 hash of the `group.csvpaths` file. The exception is: files in S3 are identified by MD5 hash because AWS calculates that for us, improving performance at the tiny risk of a hash collision. For our purposes, the MD5 is equally effective to the SHA256.|
| Named-Paths Manifest | time | The moment this version of the named-paths group was loaded. |
| Named-Paths Manifest | time_started (optional) | The beginning moment of the load. Loads are quick, so this is typically not very useful.  |
| Named-Paths Manifest | time_completed (optional) | The end moment of the load. Loads are quick, so this is typically not very useful. |
| Named-Paths Manifest | uuid |The unique identifier for this version of the named-paths group. |
| Named-Paths Manifest | manifest_path | The path to this file. |
| Named-Paths Manifest | template (optional) | The default run dir template. A string with braces-bracketed replacement tokens that determines the path within the named-results of the run directory (typically referred to as the run dir), where results are stored. The replacement tokens are of two kinds: 1. the indexes of the path segments found in the origin path. E.g. :0 for the first directory below the root, :1 for the next path segment, and so on, and 2. tokens for elements of the current datetime, e.g. :day, :month, :year, etc. |

| Named-Paths Loads Manifest | group_file_path |The path to the `group.csvpaths` file that contains all the csvpath statements in the group. Every named-paths group has this file. This file changes contents, but not name, with every load of a new version of the named-paths group. |
| Named-Paths Loads Manifest | source_path |The original path to the physical file(s) that contributed the csvpaths contained in or appended to the named-paths group in this version. |
| Named-Paths Loads Manifest | fingerprint |In most cases, the SHA256 hash of the `group.csvpaths` file. The exception is: files in S3 are identified by MD5 hash because AWS calculates that for us, improving performance at the tiny risk of a hash collision. For our purposes, the MD5 is equally effective to the SHA256.|
| Named-Paths Loads Manifest | time |The moment the named-paths group version this entry represents was loaded. |
| Named-Paths Loads Manifest | uuid | The unique identifier for the version of the named-paths group this entry represents. |
| Named-Paths Loads Manifest | username (optional) |If available, the username owning the process that loaded the version of the named-paths group this entry represents. |
| Named-Paths Loads Manifest | hostname (optional) |If available, the host where the process that loaded the version of the named-paths group this entry represents was located. |
| Named-Paths Loads Manifest | ip_address (optional) |Currently always null. `Metadata.__init__` (`csvpath/managers/metadata.py`) sets `self.ip_address = None` and the actual `socket.gethostbyname()` lookup that would populate it is commented out, because it was found to block for multiple seconds in some environments. The field exists for a future fix, not a working lookup today. |
| Named-Paths Loads Manifest | paths_manifest |The path to the `manifest.json` of the named-paths group, constructed using `[inputs] csvpaths` from `config.ini`.  |
| Named-Paths Loads Manifest | manifest_path |The path to this `manifest.json`, constructed using `[inputs] csvpaths` from `config.ini`. |

## 5. Results Run Manifest (per run)

`csvpath/managers/results/results_registrar.py` — a single dict inside each
run's own directory. This is the manifest `ResultsReferenceFinder3`/
`:manifest()` actually reads today for a selected run.

| Schema | Field | Description |
|---|---|---|
| Results Run Manifest | time |The moment this run started. |
| Results Run Manifest | uuid |A UUID that identifies the specific metadata event. Not typically used for correlation. Should be considered deprecated. |
| Results Run Manifest | run_uuid |The unique UUID assigned to this run. The CsvPaths instance generates this UUID without the triggering process or person having the opportunity to override it; however, a correlation key may be passed into the run, and stored with the run, for that purpose.  |
| Results Run Manifest | serial |True if the run completes csvpath statements serially, rather than completing a pass through all of them as each line is processed. |
| Results Run Manifest | time_completed (optional) |When the run completes this field is updated with the moment it ended. |
| Results Run Manifest | all_completed (optional) |True if all csvpath statements considered all lines to be scanned |
| Results Run Manifest | all_valid (optional) | True if all csvpath statements report they are valid. I.e. none were failed with `fail()` or due to a build-in validation error combined with a validation-mode setting of `fail`. |
| Results Run Manifest | error_count (optional) | The number of errors from all csvpath statements in the run. |
| Results Run Manifest | all_expected_files (optional) |True if all the files expected by files-mode in all the csvpaths in the named-paths group are present. There can be more than the number of files expected, for e.g. if a run outputs parquet files they won't be considered by files-mode. |
| Results Run Manifest | status |The literal string `started` when the run begins, overwritten with the literal string `complete` (not `completed`) when it finishes. See `ResultsRegistrar.STARTED`/`ResultsRegistrar.COMPLETE` in `results_registrar.py`. |
| Results Run Manifest | run_home |The run dir. I.e. the top level directory containing all the runs assets, which is named by the timestamp (disambiguated) of the moment it was run. |
| Results Run Manifest | named_results_name |The name of the results this manifest describes. Usually the same as `named_paths_name`, but not guaranteed: if the run is invoked with a `$`-reference as the paths name, `complete_run()` in `results_manager.py` strips it down to `ReferenceParser(pathsname).root_major` for `named_results_name`, while `named_paths_name` keeps the raw reference string. The two can genuinely differ in that case. |
| Results Run Manifest | named_paths_name |The name of the named-paths group that generated the run |
| Results Run Manifest | named_paths_uuid |The UUID that uniquely identifies the version of the named-paths group that caused the results to  exist. |
| Results Run Manifest | named_file_name |The name of the named-file this run took as it's data input. |
| Results Run Manifest | named_file_uuid |The UUID that uniquely identifies the version of the named-file that was the data source for the run. |
| Results Run Manifest | named_file_path |The path to the named-file version. |
| Results Run Manifest | named_file_size |The byte size of the named-file version used, read from the filesystem at the moment the run started. Not actually optional: `register_start()` sets it unconditionally, alongside `named_file_fingerprint`. Falls back to `0` if the file cannot be found (`FileNotFoundError`), per `_size()` in `results_registrar.py`. |
| Results Run Manifest | named_file_last_change |The last-modified timestamp of the named-file version used, read from the filesystem at the moment the run started. Not actually optional, same as `named_file_size` above. Falls back to `-1` if the file cannot be found, per `_last_change()` in `results_registrar.py`. |
| Results Run Manifest | named_file_fingerprint | The fingerprint of the named-file version used as input to this run. |
| Results Run Manifest | named_file_fingerprint_on_file | Deprecated. Do not use. |
| Results Run Manifest | hostname |If available, the name of the computer where the process that performed the run was. |
| Results Run Manifest | ip_address |Currently always null. `Metadata.__init__` (`csvpath/managers/metadata.py`) sets `self.ip_address = None` and the actual `socket.gethostbyname()` lookup that would populate it is commented out, because it was found to block for multiple seconds in some environments. The field exists for a future fix, not a working lookup today. |
| Results Run Manifest | username |If available, the user owning the process that performed the run. |
| Results Run Manifest | method |The run method is one of collect_paths, fast_forward_paths, next_paths, collect_by_line, fast_forward_by_line, next_by_line. Methods that include the suffix `_paths` run the csvpaths in the named-paths group serially one following the other, each starting from the top of the data. The methods with the suffix `_by_line` have each csvpath statement in the named-paths group consider each line before they all start again with the next line. The difference is usually not significant, but in some cases the difference in processing order allows for different desired outcomes. |
| Results Run Manifest | manifest_path |The path to this manifest. |

## 6. Result Instance Manifest (per csvpath statement instance)

Note: standardized on singular "Result Instance Manifest" below to match
the actual class names (`Result`, `ResultRegistrar`, `ResultMetadata`),
correcting the plural "Results Instance Manifest" that had crept into the
Schema column.

`csvpath/managers/results/result_registrar.py` — a single dict inside each
run's own per-statement instance directory (one per csvpath statement in the
run). This is the manifest `ResultsReferenceFinder3` reads today for
`run_uuid`/`uuid` lookups and would read for future instance-level field
accessors.

| Schema | Field | Description |
|---|---|---|
| Result Instance Manifest | time | The moment this csvpath statement began running.  |
| Result Instance Manifest | uuid | The unique identifier of this csvpath statement's results in this run. |
| Result Instance Manifest | serial |True if the run completes csvpath statements serially, rather than completing a pass through all of them as each line is processed. |
| Result Instance Manifest | archive_name |The archive dir name at the time this result was generated. |
| Result Instance Manifest | named_results_name |The named-results name of the run that includes this result. This is the same name as the named-paths group name. |
| Result Instance Manifest | named_paths_uuid |The unique reference to the version of the named-paths group that created the run this csvpath statement result is a member of. |
| Result Instance Manifest | run |The run dir name. A timestamp with disambiguation, if needed. |
| Result Instance Manifest | run_uuid | The unique identifier of the run this csvpath statment's result is a part of |
| Result Instance Manifest | run_home | The full path to the run dir. If `[results] archive` in `config.ini` is relative, this will be a relative path. |
| Result Instance Manifest | instance_identity |The name or index of this csvpath statement within the named-paths group. |
| Result Instance Manifest | instance_index | The index of this csvpath statement within the named-paths group. |
| Result Instance Manifest | instance_home | The path to the directory containing all the result files generated by this csvpath statement during the run. This dir is always a child of the run dir.|
| Result Instance Manifest | file_fingerprints | The fingerprints of the main well-known files generated by this csvpath statement run (data.csv, meta.json, unmatched.csv, printouts.txt, errors.json, vars.json). This manifest.json is not included. In most cases SHA256, same S3-uses-MD5 exception as the other fingerprint fields in this document. |
| Result Instance Manifest | files_expected | True if every file this csvpath statement is expected to produce, per files-mode plus the always-required meta.json/errors.json/vars.json trio, is actually present on disk. False if any expected file is missing. This is the per-instance component that the Results Run Manifest's `all_expected_files` ANDs together across every csvpath in the group; it is not a static statement of whether files are expected at all. |
| Result Instance Manifest | number_of_files_expected | Deprecated. Do not use. |
| Result Instance Manifest | number_of_files_generated |Deprecated. Do not use.  |
| Result Instance Manifest | valid |True if the statement is considered valid. Note that statements are valid by default. The setting in `validation-mode` or the `fail()` function determine if a statement run results in the data being considered to be in an invalid state. |
| Result Instance Manifest | completed |True if this csvpath statement completed its scan of all lines. |
| Result Instance Manifest | source_mode_preceding |True if `source-mode:preceeding`. The meaning is that the input data came from the data.csv file output of the csvpath statement directly before this one, rather than from the original source data file. See the caveat on `preceding_instance_identity` below: which statement actually supplied that data is not always the same as which one this field's own name-adjacent metadata claims. |
| Result Instance Manifest | preceding_instance_identity (optional) |The identity of the csvpath statement recorded as immediately preceding this one, by declared position in the named-paths group (`paths[index - 1]` in `PathsManager.get_preceeding_instance_identity`). Written only when `source_mode_preceding` is true. Caveat: this is computed from declared position, not from which csvpath statement actually supplied the preceding data at runtime (`ResultsManager.get_last_named_result`, execution-order based). The two can disagree, and this field can name a csvpath that never ran, whenever an earlier csvpath in the group is skipped (`will_run` false, e.g. `run-mode: no-run`). See issue #223. |
| Result Instance Manifest | actual_data_file | The path to the data used for this csvpath statement in this run. It is either the version of the named-file that was provided when the run started, or it is the data.csv output of the preceding csvpath statement |
| Result Instance Manifest | origin_data_file | Not the pre-registration source path (that is `from`/`origin_path` in the Named-File manifests above). This is the named-file's own resolved path via the same bare-name lookup used elsewhere (`get_named_file(self.file_name)` in `Result.origin_data_file`), independent of source-mode. It exists as the contrast to `actual_data_file`: the two differ specifically when `source-mode: preceding` substitutes the previous csvpath's data.csv as the real input, in which case `actual_data_file` reflects that substitution and `origin_data_file` still points at the named-file. |
| Result Instance Manifest | named_file_name | The named-file name. |
| Result Instance Manifest | transfers (optional) |Lists the paths this csvpath statement is transferring result files to. This does not include any transfers set in the definition.json of the named-paths group. It only includes the local `transfer-mode` transfers. See issue #224. |

## 7. Archive Run Manifest (global, archive root)

`csvpath/managers/run/run_registrar.py` — a single array at the archive
root, appended to once per csvpath-statement execution, across *every*
named-paths group. This is the manifest the earlier run-ordering experiment
found unreliable as an *ordering* source (cross-group interleaving, stale
entries for deleted runs) but confirmed useful as a *discovery* source
(`ResultsReferenceFinder3._discover_run_homes` reads it, existence-filtered).

| Schema | Field | Description |
|---|---|---|
| Archive Run Manifest | time | The moment a csvpath statement within a named-paths group begins to run. |
| Archive Run Manifest | run_uuid | Uniquely identifies the run that the csvpath statement run this entry represents is a part of. |
| Archive Run Manifest | run_home | The run dir of the run this csvpath statement's output is a part of |
| Archive Run Manifest | identity | The ID or index of this csvpath statement in the named-paths group that is driving this run. |
| Archive Run Manifest | named_paths_name | The named-paths group driving the run. |
| Archive Run Manifest | named_file_name | The named-file name of the version bytes this run is applying its named-paths group to |
| Archive Run Manifest | manifest_path | The path to this manifest. |
| Archive Run Manifest | archive_name | The name of the archive dir at the time this run occurred. |
| Archive Run Manifest | archive_path | The path to the archive dir at the time this run occurred. |
| Archive Run Manifest | base_path |Deprecated. Do not use. See issue #225. |
| Archive Run Manifest | named_files_root | The location of the named-files. It is the `[inputs] files` value from `config.ini`. |
| Archive Run Manifest | named_paths_root | The location of the named-paths. It is the `[inputs] csvpaths` value from `config.ini`.|
| Archive Run Manifest | template |The template in use for the run this csvpath statement is part of. The template determines where the run dir is located within the named-results area in the archive. |
